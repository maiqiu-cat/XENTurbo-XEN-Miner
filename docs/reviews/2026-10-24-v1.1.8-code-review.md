**没有 P0/P1。三个 PR 做的就是它们说的事，实现正确且最小，测试是真的。** 新发现一条 P2（繁体界面里应用自己写的安全句子仍是英文）；三条既有的 P2 因为无密钥网关进了默认列表而更值得做（都在最初报告“最值得先做的 10 件事”的第 1、2 件里，见第五节）；其余都是 P3。

三条 P2 都是既有行为，不是这两个 PR 引入的；它们在最初报告里已是“最值得先做”的第 1、2 件事。这里重新列出，是因为 v1.1.8 把一个会限流的无密钥网关放进了默认列表，并以“Tenderly 兜底”为卖点，这三条决定了那个卖点实际值多少。行号说明：`rpc.ts:120-134, 427-446, 480-510`、`chainReader.ts:16-17, 76-78, 218, 327-343, 424-438`、`useGasPrice.ts:36, 84`、`rpc.ts:307`、`probe-release-chain.mjs` 的 6 项批量、`.env.example`、`rpc.test.ts:172-194`、`rpcBatchCompatibility.test.ts:27-58`、`chainReaderBatches.test.ts` 的上限、ethers 6.17.0 的 `provider-jsonrpc.js:689-691` 与 `fetch.js:26, 473-476` 是我对回文件的；其余行号出自子代理。

**P2-r1 `FallbackProvider` 从不在请求时切换；第 4 位的 Tenderly 不会服务任何一次读取，除非另外三个都探活失败**【既有（= 原报告 A1）；代码已核对；数字为子代理实测】
- `rpc.ts:128-134`：`priority: index + 1`、`stallTimeout: 2500`、`weight: 1`、`quorum: 1`。ethers 6.17 `provider-fallback.js` 的 `#waitForQuorum` / `checkQuorum`：quorum 为 1 时，第一个 runner 的任何结局——结果、错误、包括 TIMEOUT——一出现就被返回；2.5 s 后由 staller 启动的第二个 runner 加进来时，`interesting` 已经算过，它的回答只在主节点结束时才被看一眼，而那时主节点的条目排在前面、平手时它赢。
